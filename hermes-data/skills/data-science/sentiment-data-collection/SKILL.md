# 舆情数据采集工作规范

## 额外核心原则

1. **社媒授权规范**：需要扫码授权时，必须将二维码图片返回给用户，不能自行操作授权
2. **全量存储原则**：所有抓取的数据必须 100% 存入数据库，不限本次分析用途，可供后续其他分析复用
3. **向量检索原则**：后续从本地数据库挖掘内容时，**必须使用 `vector_search`** 而非 `keyword_search`，确保语义相关性

## 核心原则

> **对数据敏感、对内容采集严谨、对分析有理有据。使用最可信的数据源，对所有引用进行标注。**

这是最高优先级工作标准，不可跳过任何步骤。

---

## 完整工作流程

```
第一步：多平台关键词搜索
        ↓ 获取所有 URL（不限数量，全部保留）
第二步：逐条 firecrawl_scrape 访问每个 URL
        ↓ 获取每个页面的完整正文内容
第三步：社媒平台 crawl_media 采集
        ↓ 微博/小红书/抖音/B站 等平台真实讨论
        ↓ 需授权时 → 立即返回二维码给用户扫码
第四步：save_crawled_data 存入数据库
        ↓ 全部 URL 内容都要存，不是只存几条
第五步：keyword_search / get_recent_data 验证数据量
        ↓ 数据不足 → 返回第二步继续补采
第六步：vector_search 向量匹配查询本地数据
        ↓ 语义检索获取最相关内容，而非 keyword_search
第七步：Insight Engine 分析 + 报告生成
        ↓ 数据真实、引用标注、结论可溯源
```

---

## 禁止行为

- ❌ 搜索完只挑几条"看起来重要"的存
- ❌ 用搜索摘要替代网页原文内容
- ❌ 跳过 firecrawl_scrape 不逐条访问
- ❌ 忽略社媒数据，只用媒体报道
- ❌ 数据不够就出报告，"差不多得了"
- ❌ 引用数据不标注来源

---

## 数据质量标准

| 维度 | 最低要求 |
|------|---------|
| URL 覆盖率 | 搜索返回的 URL **100%** 要访问 |
| 内容完整度 | 存入库的是**完整正文**，不是摘要 |
| 社媒覆盖 | 至少覆盖 3 个国内主流社媒平台 |
| 引用标注 | 报告每个数据点必须标注来源 URL |
| 数据量 | 数据库查询结果不足则继续补采 |

---

## 报告引用规范

每个数据点在报告中必须标注：
- 数据库记录 ID
- 来源平台
- 原文 URL
- 抓取时间
- 原文关键摘录（verbatim）
- 向量匹配相关性评分（如使用 vector_search）

---

## 向量检索标准

- **必须使用 `vector_search`** 从本地数据库获取语义相关内容
- 不能仅用 `keyword_search`（它是模糊的 LIKE 匹配，不够精准）
- 检索结果需包含相关性评分，低于阈值的内容不纳入分析
- 向量检索后仍需核实原文内容，不能直接信任摘要

---

## 自检清单（出报告前必查）

- [ ] 所有搜索到的 URL 都访问了吗？
- [ ] 每条内容都是完整正文而非摘要？
- [ ] 社媒平台 crawl_media 采集了吗？
- [ ] 数据库里存了多少条记录？（确认全量存储）
- [ ] 每个数据引用都标注了来源吗？
- [ ] 数据量够支撑分析结论吗？
- [ ] 从数据库挖掘时是否使用了 vector_search？
- [ ] 如需授权，二维码是否已返回给用户？
